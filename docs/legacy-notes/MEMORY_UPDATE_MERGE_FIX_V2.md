# 记忆更新合并机制 V2 - 保守策略，彻底防止内容丢失

## 更新时间
2025-01-XX

## 版本历史

- **V1**：基础内容合并，检查前5个关键词
- **V2**：更严格的保守策略，基于覆盖率和长度比判断 ⭐

## 问题背景

用户反馈：**仍然存在问题** - 即使实现了 V1 的合并机制，仍然"大量地导致前面的记忆被删除"。

### V1 的问题

**旧的检测逻辑**（V1）：
```typescript
// ❌ 太宽松！只检查前5个关键词
const oldContentWords = existingMemory.content.split(/\s+|。|，/).filter((w: string) => w.length > 2)
const newContentIncludesOld = oldContentWords.slice(0, 5).every((word: string) => memory.content.includes(word))

if (newContentIncludesOld) {
  mergedContent = memory.content  // 直接覆盖
}
```

**问题**：
- 只检查前5个词 → 如果 AI 只提到开头几个词，就会覆盖整个旧内容
- 导致后面的大量信息丢失

**示例**：
```
旧内容 (200字):
  张三，25岁设计师，高挑温和，性格内向但善良，喜欢阅读和绘画。
  她从小在单亲家庭长大，母亲独自抚养她。她最怀念和妈妈做饭的时光。
  她的梦想是开一家自己的设计工作室...

AI 返回 (50字):
  张三，25岁设计师。今天她透露了对未来的规划...

检测结果: "张三" "25岁" "设计师" 都在 → 认为包含旧内容
执行覆盖 → 丢失 150 字的重要信息！❌
```

## 解决方案 V2：保守策略

### 核心理念

**宁可追加冗余，也不能丢失信息！**

采用更严格的判断标准：
1. **覆盖率检测**：检查 AI 包含了多少比例的旧内容（而不是只看前几个词）
2. **长度比检测**：检查新内容是否明显增长（说明 AI 真的整合了）
3. **保守默认**：如果不确定，就追加而不是覆盖

### 详细判断逻辑

```typescript
// 情况1：AI 使用了【新增】标记
if (content.includes('【新增】')) {
  → 直接使用（AI 已经整合了旧+新）
}

// 情况2：新内容明显更长(+20%) 且 包含70%以上的关键词
else if (lengthRatio >= 1.2 && coverageRatio >= 0.7) {
  → 使用新内容（AI 做了完整整合）
}

// 情况3：新内容包含90%以上的关键词
else if (coverageRatio >= 0.9) {
  → 使用新内容（AI 重写了内容）
}

// 情况4：默认保守策略
else {
  → 追加到旧内容末尾（不覆盖，保护所有旧信息）
}
```

## 实现代码

**位置**：`src/app/api/chat/summary/route.ts:668-708`

```typescript
// 智能合并内容：采用保守策略，优先保留旧内容
let mergedContent = memory.content
const hasNewAddition = memory.content.includes('【新增】') || memory.content.includes('[新增]')

if (hasNewAddition) {
  // 情况1：AI 明确标记了新增部分，直接使用AI返回的内容（包含旧+新）
  mergedContent = memory.content
  console.log(`📝 检测到【新增】标记，使用AI整合的内容`)
} else {
  // AI 没有标记新增，需要判断如何合并

  // 检查新内容长度是否明显增加（说明AI可能整合了旧内容+新信息）
  const oldLength = existingMemory.content.length
  const newLength = memory.content.length
  const lengthRatio = newLength / oldLength

  // 检查关键词覆盖率
  const oldContentWords = existingMemory.content.split(/\s+|。|，|、|；/).filter((w: string) => w.length > 2)
  const significantWords = oldContentWords.filter((w: string) => w.length > 3) // 更有意义的词

  // 计算旧内容有多少比例被新内容包含
  const matchedWords = significantWords.filter((word: string) => memory.content.includes(word))
  const coverageRatio = significantWords.length > 0 ? matchedWords.length / significantWords.length : 0

  console.log(`📊 内容分析: 旧=${oldLength}字, 新=${newLength}字, 长度比=${lengthRatio.toFixed(2)}, 覆盖率=${(coverageRatio * 100).toFixed(1)}%`)

  if (lengthRatio >= 1.2 && coverageRatio >= 0.7) {
    // 情况2：新内容明显更长(+20%)且包含70%以上的关键词 → AI做了完整整合
    mergedContent = memory.content
    console.log(`✅ 新内容更长且覆盖率高，使用新内容`)
  } else if (coverageRatio >= 0.9) {
    // 情况3：新内容包含90%以上的关键词，即使长度相近 → AI重写了内容
    mergedContent = memory.content
    console.log(`✅ 覆盖率很高(${(coverageRatio * 100).toFixed(1)}%)，使用新内容`)
  } else {
    // 情况4：保守策略 - 追加到旧内容，不覆盖
    // 这样可以确保不丢失任何信息，即使格式可能不够完美
    mergedContent = `${existingMemory.content}\n\n【新增信息】${memory.content}`
    console.log(`⚠️ 覆盖率较低(${(coverageRatio * 100).toFixed(1)}%)，追加新内容保护旧信息`)
  }
}
```

## 关键改进点

### V1 → V2 的改进

| 维度 | V1 | V2 |
|------|----|----|
| 检测方式 | 前5个关键词 | 全部关键词覆盖率 |
| 长度考虑 | ❌ 不考虑 | ✅ 考虑长度比 |
| 默认策略 | 覆盖 | 追加（保守） |
| 词长过滤 | >2字 | >3字（更有意义） |
| 日志详细度 | 简单 | 详细（含比例） |
| 信息丢失风险 | ⚠️ 中等 | ✅ 极低 |

### 为什么 V2 更好？

1. **覆盖率检测**：
   - V1: 只看前5个词 → 容易误判
   - V2: 计算全部关键词的覆盖率 → 准确

2. **长度验证**：
   - V1: 不考虑长度 → AI 可能省略了大量信息
   - V2: 必须新内容更长(+20%) → 确保 AI 真的整合了

3. **保守默认**：
   - V1: 不确定时可能覆盖 → 有风险
   - V2: 不确定时追加 → 零风险

4. **详细日志**：
   - V1: 简单提示
   - V2: 显示长度比、覆盖率百分比 → 方便调试

## 配合 Prompt 优化

虽然后端已经有强保护，但仍然鼓励 AI 使用【新增】标记：

**Prompt 强调**：
```
2. **更新现有记忆时**:
   - 必须提供existing_id（从上面【现有记忆表格】中获取）
   - ⭐ 重要：content字段应该包含【完整的旧内容 + 【新增】新信息】
   - 示例格式：
     "张三，25岁设计师，高挑温和，性格内向但善良。
      【新增】今天透露自己从小在单亲家庭长大..."

```

这样 AI 更容易理解应该如何更新记忆。
